# بریف ادغام «بلاگ رودیپ» در وبسایت شما

این سند برای توسعه‌دهندهٔ وبسایتی است که قرار است این بلاگ به آن اضافه شود. بلاگ یک محصول کامل و آماده است، نه یک ایده: فرانت‌اند React ساخته‌شده و تست‌شده دارد، بک‌اند مرجع Django دارد، و قرارداد API مشخص است. کار شما «وصل کردن» است، نه «ساختن از صفر».

- مخزن: https://github.com/damyarpro/blogroadeep
- دموی زندهٔ فرانت: https://damyarpro.github.io/blogroadeep/
- قرارداد API: `frontend/src/lib/types.ts` و `frontend/src/lib/api.ts`
- بک‌اند مرجع (Django 5 + DRF، با تست): پوشهٔ `backend/`

**الزامات محصولی:** بدون صفحهٔ ورود و ثبت‌نام برای کاربران؛ صفحهٔ نوشتن مقاله (ادیتور فارسی کامل)، تاریخچهٔ مقالات، دیدگاه با تأیید، و SEO باید از روز اول کار کنند. زبان فارسی، راست‌چین.

---

## ۱. تصویر کلی ادغام

بلاگ زیر مسیر `‎/blog/` سایت شما قرار می‌گیرد (مسیر قابل تغییر است، ولی در کل سند همین فرض شده):

```
example.com/blog/            ← صفحهٔ اصلی بلاگ (SPA)
example.com/blog/articles/…  ← مقالات (مسیرهای SPA)
example.com/api/blog/…       ← API بلاگ
example.com/media/blog/…     ← تصاویر آپلودی
example.com/blog/sitemap.xml ← سایت‌مپ بلاگ
example.com/blog/feed/       ← RSS
```

دو راه برای بک‌اند دارید؛ **راه A را توصیه می‌کنیم**:

### راه A — استقرار بک‌اند آماده (سریع، کم‌ریسک)
بک‌اند Django موجود را به‌عنوان یک سرویس مجزا کنار سایتتان بالا بیاورید (Docker یا gunicorn + هر روشی که دارید) و در وب‌سرور اصلی (Nginx/Caddy/…) این مسیرها را به آن reverse-proxy کنید:
`/api/blog/` ، `/media/blog/` ، `/blog/sitemap.xml` ، `/blog/robots-blog.txt` ، `/blog/feed/`

- دیتابیس: PostgreSQL خودتان (env: `DATABASE_URL`) یا SQLite برای شروع
- همهٔ تنظیمات از env: `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CORS_ALLOWED_ORIGINS`, `DJANGO_SITE_DOMAIN` (دامنهٔ سایت شما، برای لینک‌های سایت‌مپ/RSS), `DJANGO_MAX_UPLOAD_SIZE`
- دستور `python manage.py seed_blog` دادهٔ نمونهٔ فارسی می‌سازد (برای تست ادغام)

### راه B — پیاده‌سازی قرارداد در بک‌اند فعلی خودتان
اگر می‌خواهید همه‌چیز داخل استک فعلی‌تان باشد، همان قرارداد `types.ts` را پیاده کنید. خلاصهٔ قرارداد در بخش ۵ آمده و جزئیات کامل (مدل داده، پاک‌سازی HTML، معیارهای پذیرش) در سند جداگانهٔ `BACKEND_BRIEF.md` مخزن است. فرانت نباید حتی یک خط تغییر کند.

## ۲. نصب فرانت بلاگ

فرانت یک SPA ایستاست؛ خروجی build را در سایتتان سرو کنید:

```bash
cd frontend
npm ci
VITE_BASE=/blog/ VITE_API_URL=https://example.com/api/blog npm run build
# خروجی: frontend/dist/
```

- `dist/` را زیر `‎/blog/` سرو کنید
- **فال‌بک SPA لازم است:** هر مسیر `‎/blog/*` که فایل ایستا نبود باید `blog/index.html` را برگرداند (در Nginx: `try_files $uri /blog/index.html;`)
- فونت وزیرمتن و همهٔ استایل‌ها داخل باندل است؛ به CDN خارجی وابسته نیست
- حالت تاریک، راست‌چین و ریسپانسیو داخل خود بلاگ مدیریت می‌شود

اگر می‌خواهید هدر/فوتر سایت اصلی دور بلاگ باشد، گزینهٔ ساده iframe نیست؛ بلاگ هدر و فوتر خودش را دارد و توصیه می‌کنیم به‌عنوان یک بخش مستقل با لینک متقابل به سایت اصلی سرو شود. یکدست‌سازی بصری عمیق‌تر، تغییر فرانت می‌خواهد و خارج از این بریف است.

## ۳. احراز دسترسیِ نوشتن (بدون ورود و ثبت‌نام)

هیچ صفحهٔ ورود/ثبت‌نامی برای کاربران عادی وجود ندارد و نباید ساخته شود. برای مسیرهای نوشتن یکی از این دو را پیاده کنید:

1. **کلید ثابت (پیش‌فرض توصیه‌شده):** env با نام `WRITE_API_KEY`؛ همهٔ مسیرهای `‎/api/blog/admin/…` هدر `X-Api-Key` را الزامی کنند؛ نبود/اشتباه بودن کلید → `401`. کلید فقط دست مدیر محتواست.
2. **سوار شدن روی سشن ادمین سایت خودتان:** اگر سایتتان ورود مدیریتی دارد، همان سشن/گارد را جلوی مسیرهای admin بلاگ بگذارید. باز هم هیچ UI ورود جدیدی ساخته نمی‌شود.

ثبت دیدگاه برای عموم آزاد است؛ فقط rate-limit بگذارید (مثلاً ۵ دیدگاه در دقیقه بر IP).

## ۴. قابلیت‌هایی که باید بعد از ادغام کار کنند

- **صفحهٔ نوشتن مقاله** (`/blog/admin/posts/new`): ادیتور فارسی با تراز، هایلایت، جدول، تبدیل ارقام و حروف عربی به فارسی، نیم‌فاصله، آپلود تصویر داخل متن، کاور، فیلدهای SEO با پیش‌نمایش گوگل، تقویم جلالی برای تاریخ انتشار، ذخیرهٔ خودکار
- **تاریخچه:** فهرست همهٔ مقالات (شامل پیش‌نویس‌ها) با فیلتر و جستجو + در صورت پیاده‌سازی راه B، نسخه‌بندی هر ذخیره (Revision) طبق `BACKEND_BRIEF.md`
- **دیدگاه:** فرم عمومی زیر هر مقاله → صف تأیید → نمایش پس از تأیید؛ تأیید تکی و گروهی از پنل
- **SEO:** متای هر مقاله با fallback، سایت‌مپ، RSS، robots (بخش ۶)

## ۵. خلاصهٔ قرارداد API (برای راه B)

| متد | مسیر (نسبت به `/api/blog`) | توضیح |
|---|---|---|
| GET | `/posts/` | فقط منتشرشده‌ها؛ صفحه‌بندی ۹تایی `{count,next,previous,results}`؛ `?page= ?search= ?category= ?tag= ?ordering=` |
| GET | `/posts/<slug>/` | جزئیات + SEO + دیدگاه‌های تأییدشده؛ پیش‌نویس → 404؛ نامک فارسی مجاز |
| POST | `/posts/<slug>/comments/` | `{name,email,body}` → ثبت تأییدنشده، `201` |
| GET | `/categories/` , `/tags/` | با `post_count` |
| CRUD | `/admin/posts/…` + `slug-available/` + `uploads/` + `comments/…` + `categories/` + `tags/` | با `X-Api-Key`؛ جزئیات کامل در `BACKEND_BRIEF.md` |

**الزام امنیتی:** `content` مقالات HTML است و فرانت مستقیم رندرش می‌کند؛ در هر ذخیره سمت سرور با کتابخانهٔ معتبر پاک‌سازی شود (لیست دقیق تگ‌های مجاز در `BACKEND_BRIEF.md`، بخش ۷).

## ۶. ادغام SEO با سایت اصلی

- **سایت‌مپ:** سایت‌مپ بلاگ را به‌صورت مستقل در `‎/blog/sitemap.xml` سرو کنید و در **sitemap index** سایت اصلی‌تان رفرنس بدهید (یا در robots.txt اصلی، `Sitemap:` جدا اضافه کنید)
- **robots.txt اصلی سایت:** مسیرهای `‎/blog/admin` و `‎/api/blog/admin` را disallow کنید؛ خود صفحات بلاگ index شوند
- **دامنهٔ canonical:** env مربوط به دامنه (`DJANGO_SITE_DOMAIN` یا معادلش) را روی دامنهٔ اصلی بگذارید تا لینک‌های سایت‌مپ/RSS/canonical درست ساخته شوند
- **RSS:** `‎/blog/feed/` را در `<head>` سایت اصلی با `<link rel="alternate" type="application/rss+xml">` معرفی کنید
- نامک مقالات پس از انتشار تغییر نکند (شکستن لینک = افت سئو)

## ۷. معیارهای پذیرش

- [ ] `example.com/blog/` بالا می‌آید؛ رفرش روی مسیرهای داخلی (مثل `‎/blog/articles/فلان`) هم کار می‌کند (فال‌بک SPA)
- [ ] فرانت **بدون تغییر کد** به API وصل شده؛ فهرست، جستجو، فیلتر، جزئیات مقاله کار می‌کنند
- [ ] چرخهٔ کامل: نوشتن مقاله در `‎/blog/admin` → انتشار → دیدن در سایت → آمدن در سایت‌مپ و RSS
- [ ] مسیرهای نوشتن بدون کلید/سشن → `401`؛ ثبت دیدگاه عمومی کار می‌کند و تا تأیید نمایش داده نمی‌شود
- [ ] آپلود تصویر (متن و کاور) کار می‌کند و از `‎/media/blog/` سرو می‌شود؛ غیر تصویر و بالای ۵MB رد می‌شود
- [ ] `<script>` در محتوای ذخیره‌شده باقی نمی‌ماند (تست)
- [ ] سایت‌مپ بلاگ در sitemap index اصلی رفرنس شده و از Search Console معتبر است
- [ ] HTTPS، CORS محدود به دامنهٔ اصلی، و هیچ secret ای در کد یا مخزن نیست

## ۸. غیرهدف‌ها

ورود/ثبت‌نام کاربران، پروفایل، چندنویسنده، یکپارچه‌سازی بصری هدر/فوتر سایت اصلی با بلاگ، خبرنامه، جستجوی سراسری بین سایت و بلاگ.
